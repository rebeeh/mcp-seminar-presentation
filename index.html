Core Topology: Hosts, Clients & Servers

MCP Host

The container environment (Claude Desktop, Cursor, IDEs) initiating model queries and securing user consent.

MCP Client

Embedded protocol consumer in the host that negotiates capabilities and manages RPC connections.

MCP Server

Lightweight service exposing specific tools, resources, and prompt templates over standardized transports.

07 / 21

Runtime Mechanics: Host & Client

MCP Hosts manage user authorizations and inference loops. The embedded client dynamically negotiates capabilities with local or remote server endpoints.

This separates tool logic from client code, enabling instant extensibility without recompiling the host application.

08 / 21

MCP Server: Internal Architecture

Capability Exposure

Servers declare capability manifests listing available tools, readable resources, and prompt templates during handshake.

Transport Layer

Handles incoming RPC streams via stdio or Server-Sent Events (SSE), mapping standard calls to local actions.

Context Isolation

Executes commands within isolated sub-processes, preventing unauthorized host filesystem access.

09 / 21

Protocol Primitives: Core Capabilities

Tools (Model-Driven)

Executable functions exposed by servers that models invoke to alter state or execute computations.

Resources (App-Driven)

Passive, readable data streams exposed via URI schemas (`file:///`, `postgres://`) for model grounding.

Prompts (User-Driven)

Pre-packaged interaction templates provided by servers to guide complex multi-step AI reasoning.

10 / 21

Spotlight: Context Resources

Read-Only Data Access
  • URI Addressing: Resources use standard URIs like postgres://db/table or file:///logs/app.log.
  • Real-time Subscriptions: Clients can subscribe to resource updates and receive dynamic notifications when underlying data shifts.
Dynamic Data Stream Ingestion

Active Function Execution
  • Model Choice: The AI model evaluates tool descriptions and JSON schemas to decide when and how to invoke tools.
  • State Modification: Tools can perform write operations, API calls, or run scripts, backed by human authorization gates.

Security Model: Sandboxing & Consent

  • Directory Roots Boundary: Restricts server file access strictly to user-approved workspace paths.
  • Human-in-the-Loop Approval: Prompting users explicitly before invoking state-modifying tools.
  • Token Scrubbing: Prevents credential leakage across unverified remote server endpoints.
Zero-Trust Execution Scope

Architectural Pros: System Advantages

Scalability

Add enterprise integrations without needing host client updates or model retraining.

User Privacy

Data stays inside local host environments; secrets never leak to external LLM providers.

Interoperability

Open specification supported by Anthropic and Linux Foundation avoids vendor lock-in.

18 / 21

Trade-offs & Engineering Challenges

Serialization Overhead

JSON-RPC marshaling over stdio/SSE introduces slight millisecond latencies.

Context Bloat

Exposing large resource schemas consumes valuable LLM input context window space.

Server Runtimes

Requires local runtime management (Node.js/Python) for executable MCP servers.
